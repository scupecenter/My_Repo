# Open questions (P0)

These are only the real gaps found while writing the spec. Each one has a proposed default, which is used as a configurable setting until the owner decides.

The first three are carried over from CLAUDE.md "Still open":
- **S1. Documents for stages 4–10.** They are seeded as drafts (marked TBD in `task-catalogue.csv`), to be reviewed in the Document Library. *Default:* drafts are not mandatory until they are published.
- **S2. Real names per role.** They are entered after go-live. *Default:* synthetic users only.
- **S3. Final Aljeel brand.** *Default:* frappe-ui tokens in one file.

| # | Gap (source) | Proposed default |
|---|---|---|
| Q1 | **The Master upload has no `_tpl` sheet.** CLAUDE.md rejects uploads without an embedded ID. The live Master file contains no `_tpl` sheet, but must be uploadable during migration and the 1-month parallel run. | The PMIS issues a "Master template" by adding `_tpl` (TPL-MASTER, version) to the user's copy once. Until then, an admin-only "legacy Master import" path accepts it, identified by sheet names and headers, and writes every use to the System Log. |
| Q2 | **D-1 start where RFI is N/A.** CLAUDE.md measures D-1 from the Site RFI date. Hot / Cold Swap and sites with no CW, GECOL or HLC have no Site RFI (BP §03). BP §06 says D-1 is not measured for Swap. | D-1 starts from MS4. Where RFI is N/A, it starts from MS1 (the base date of gate CA). D-1 is not measured for Hot / Cold Swap. The Master SLA sheet (column Y, which starts from Site Release) needs the same fix for the parallel-run comparison. |
| Q3 | **RFI for Swap sites.** BP §03 and the SLA sheet say RFI is N/A for Hot / Cold Swap. Site Calc F and Master BQ decide RFI from the flags AA:AD only. | Follow the Master formula (flags), so the parallel run matches. Add an alert when a Hot / Cold Swap site has any of AA:AD = Yes. |
| Q4 | **The holidays table is empty.** Setting "Public Holidays" (F:G) has no rows, so every SLA currently ignores holidays. | The admin enters the Libyan public holidays for 2026–2027 before the pilot. Until then SLA counts Fri / Sat only, and a banner warns "holiday table empty". |
| Q5 | **Document step codes differ.** CLAUDE.md seeds "B4 STA / ST report", but in the blueprint step table B4 is the CW survey and B5 is STA / ST. CLAUDE.md seeds "B9 MOS proof" only, but B8 (tower MOS) has the same evidence. | Attach the STA / ST report to step B5 and the MOS proof to both B8 and B9. Confirm both. |
| Q6 | **Warehouse need for IP Router Only sites.** D72 applies a fixed need to every TE site: Router 1, Cabinet 1, Battery 2, LPU 2, plus sectors. An IP Router Only site (AF = Yes) probably needs only the router, so its TE Dispatch Complete would never be reached. | When AF = Yes and AE = N/A, the need is Router = 1 and every other unit = 0, as a configurable rule per scenario. Confirm before the WH build. |
| Q7 | **Delay that no period covers.** BP §14 attributes the days above SLA to the executor (R). BP §09 says days not attributed are charged to no one. | Show these days on the default party (R), tagged "default (R)" and kept separate from approved attributions. The contractor scorecard counts approved attributions only (BP §06). |
| Q8 | **Role list mismatch.** Setting StaffRole (15 values, for example "Team Lead (GECOL)", "Team Lead (Fiber)", "CW Engineer") does not match the 6 main roles and 9 sub-roles in CLAUDE.md. | The PMIS uses the CLAUDE.md roles. Import maps the Master values (Team Lead (CW) → CW Team Lead, CW Engineer / Site Engineer → Site Engineers (CW), Team Lead (GECOL) → GECOL Power Team, and so on). The mapping table is editable and approved by the owner. |
| Q9 | **Gate date vs extra conditions.** CLAUDE.md says the gate date equals the previous milestone date. The Master gates AX, CA and CV take the latest of that date, the Access / PTW permit dates and the Commissioning Power Safe Date, and stay blank while a Stop Work is active. | Follow the Master formulas (rules.md §2.2). The CLAUDE.md wording covers the base case. An ADR records the refinement. |
| Q10 | **Region names.** The Master stores "Tripoli Area", "Middle Area" and so on. CLAUDE.md uses "Tripoli", "Middle" and so on. | Store a region code with an English and an Arabic label. Import maps "X Area" → X. |
| Q11 | **Several issues per site vs the Master.** The Master holds one issue per site (GA:GE). The PMIS allows several. For the parallel-run export, which issue goes into GA:GE? | Export the oldest open issue, or the latest closed one when none is open, and append "+N more" in Remark. |
| Q12 | **Meetings register has no source.** CLAUDE.md lists Meetings, but it has no Master sheet and no blueprint fields. | Minimal fields: date, title, type, attendees, sites, minutes file, and action items (owner, due date, status). Owner to confirm. |
| Q13 | **B-6 is always 0 for analysis sites.** The Master has a single submission date (AR) for both the analysis report and the layout. B-6 therefore runs AR → AR when an analysis exists (D47). | Keep the Master behaviour for the parallel run. Propose a separate Layout Submitted Date after the Master is retired. |
| Q14 | **SLA step count.** D64 says 44 steps, but SLA sheet columns D:AV hold 45 step columns (B-10a and B-10b are separate). | Treat the 45 columns as the source of truth. 44 counts B-10 as one step. |
| Q15 | **Swap sites and stage 1 (A1, A3).** Expansion drops A1 and A3 (CLAUDE.md). Nothing says whether Hot / Cold Swap sites, which are existing sites, need a search, a SAR and an acquisition. | A1 and A3 apply by default, and a scenario template setting can mark them N/A. Confirm. |
| Q16 | **Health index and Final Closure KPI formulas.** These are new PMIS features with no source formula (rules.md §6.1, §9). | Equal weights across the 6 factors. The % closed base is HOTO-achieved sites. FAC age is counted from DLP End. The owner reviews all three before P1. |
| Q17 | **TE PAC e-signature.** BP §05 says TE PAC is e-signed by the project team. CLAUDE.md says acceptance documents are filled, signed, scanned and uploaded. | Scanned upload only (CLAUDE.md). E-signature is deferred. |
| Q18 | **Assignment overlaps and level order.** CLAUDE.md now makes role assignment many-to-many with validity dates. It does not say whether two rows of the same role with overlapping dates may exist, or whether a higher permission level includes the lower ones. | One active row per user and role at a time; a bulk assign skips existing rows. The levels are ordered view < entry < review < approve < admin, and each includes the lower ones (AU-10, AU-11, MX-02b). |
