# ADR 0001: Stack and monorepo layout

- Status: Accepted (tech-lead), 2026-10-24
- Deciders: tech-lead. The product owner fixed the platform (NestJS, PostgreSQL, internal server, never cloud).
- Related: CLAUDE.md "Default stack", ORCHESTRATION.md folder ownership.

## Context
The PMIS replaces the Excel Site Master. It runs on one internal server with a standby server and no cloud services. Eight agents work in parallel, each in its own folders. They need one place to find the API contract and one build. The web app must be able to work against mocks before the API exists ("contract first").

## Decision
1. **Runtime and languages.** Node.js 22 LTS and TypeScript 5 in strict mode everywhere. pnpm workspaces with a single lockfile. No Turborepo for now: pnpm filters are enough at this size.
2. **Layout** (all under `pmis/`):

   | Path | What | Owner |
   |---|---|---|
   | `apps/web/` | React 18, Vite, Tailwind with Radix/shadcn, TanStack Query and Table, react-i18next (EN and AR, RTL), ECharts. Tokens are imported from `design/tokens.css`. | frontend-engineer |
   | `apps/api/src/` | NestJS API and the BullMQ worker. They are one image with two entry points (`main.ts`, `worker.ts`). | backend-engineer |
   | `apps/api/prisma/`, `db/`, `tools/master-import/` | Prisma schema, migrations, raw SQL (RLS, triggers), seed, importer mapping | database-engineer |
   | `contracts/openapi.yaml` | The only source of truth for the HTTP API | tech-lead |
   | `packages/contracts/` | Generated, never edited by hand: `openapi-typescript` types, a typed fetch client, and MSW handlers with example data. It is regenerated by `pnpm contracts:gen`, and CI fails if the output is stale. | tech-lead (generator config only) |
   | `tests/` (Playwright E2E, contract tests), `docs/test-plans/` | | qa-engineer |
   | `infra/`, `.github/workflows/`, `Dockerfile*` | Compose, proxy, backup scripts, CI | devops-security |
3. **API style.** REST over JSON, with snake_case property names to match the database and the importer mapping. The base path is `/api/v1`. Errors use RFC 9457 `application/problem+json`. Lists use cursor pagination. Optimistic concurrency uses ETag and `If-Match` (see `contracts/openapi.yaml`, "Conventions").
4. **Data.** PostgreSQL 16 through Prisma. Anything Prisma cannot express (RLS, triggers, exclusion constraints, SECURITY DEFINER functions) lives in raw SQL in `db/sql/` and is applied by a Prisma migration. Background jobs run on BullMQ with Redis 7. Files go to MinIO (ADR 0008).
5. **Deployment.** Docker Compose on the internal server. It runs these services: `proxy` (TLS from the internal CA), `web` (static files), `api`, `worker`, `postgres`, `redis` and `minio`. The standby server receives WAL streaming and MinIO replication.
6. **Contract versioning.** `info.version` follows semver. While the contract is at 0.x, a minor version may break compatibility, but every breaking change gets an entry in an ADR under `docs/adr/` (a new ADR, or an "Amendments" section of the ADR that owns the area) before the PR merges. From 1.0 on, a breaking change needs a new base path (`/api/v2`). CI runs `redocly lint` and fails a PR that changes behaviour without changing `contracts/openapi.yaml`.
7. **Quality gates in CI.** Typecheck, ESLint and Prettier, Vitest (unit tests), Supertest against a real Postgres in a container (API tests, including RLS tests that connect as `pmis_app`), Playwright against Compose (E2E), and contract lint and drift.

## Consequences
- One lockfile and one generated client mean the web and the API cannot drift silently. In return, any contract change needs a regeneration commit.
- snake_case JSON looks unusual in a TypeScript front end. It is accepted so that one name is used across the importer, the database, the API and the exported Master.
- Bundling the worker with the API keeps deployment simple. A heavy job (zip export, Master import) can be scaled by running a second `worker` container.
- Using no cloud services rules out managed authentication proxies, managed object storage and SaaS email. Email goes through the company Exchange relay (SMTP), configured by devops.
